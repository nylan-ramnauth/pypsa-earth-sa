## Summary

Audit the provenance of every input value used by the ZA 2023 calibrated baseline and selected sensitivities.

The goal is to know, field by field, which data are actually observed Eskom 2023 data, which are derived from Eskom 2023 data, which are PyPSA-RSA-derived 2023 scenario assumptions, which are generic/historical technical assumptions, and which are future or audit-only references.

This module is necessary because the local `Benchmark_2023 / S_2023BM` scenario was created by the project from PyPSA-RSA `Coal_Flexibilisation` inputs plus local 2023 edits. It is not an upstream PyPSA-RSA GitHub scenario. Therefore, the project must not overclaim that every input is documented RSA 2023 data or measured Eskom 2023 data.

## Objective

Produce a clear, machine-readable provenance classification for all data used by the 2023 model path.

Primary deliverable:

```text
data/za_audit/za_2023_input_provenance_classification.csv
```

This audit should drive:

- which source files Module 13l packages into Earth
- how final validation reports describe the 2023 calibrated baseline
- which inputs are safe to call observed 2023 data
- which inputs must be described as scenario assumptions
- which copied RSA files are future references with no 2023 effect
- which `S_2023BM` scenario columns are effective drivers of the Earth 2023 model and which are inherited/no-op settings

## Provenance Classes

Use these classes exactly unless the audit finds a necessary addition:

| Class | Meaning |
|---|---|
| `observed_eskom_2023` | Direct observed Eskom 2023 data used as model input or validation target |
| `derived_from_eskom_2023` | Computed from observed Eskom 2023 data, with transformation documented |
| `rsa_derived_2023_scenario_assumption` | Local PyPSA-RSA-derived assumption selected for the 2023 benchmark scenario |
| `rsa_generic_or_historical_technical_assumption` | RSA technical parameter not proven to be a measured 2023 value |
| `project_local_2023_assumption` | Assumption created by this project for the 2023 calibration |
| `future_scenario_assumption_no_2023_effect` | Future/planning assumption present in copied workbooks but inactive for 2023 |
| `audit_only_reference` | Source retained for documentation/audit but not used at runtime |
| `generated_intermediate` | Generated by the Earth workflow from other classified sources |
| `unused_or_stale` | Present in files/config but not used by current runtime path |
| `unknown_requires_source_review` | Used or potentially used, but provenance cannot be classified from local evidence |

The audit should prefer `unknown_requires_source_review` over unsupported certainty.

## Scenario Setting Effect Classes

For every column in the local `S_2023BM` scenario row, assign an effect class:

| Class | Meaning |
|---|---|
| `active_direct` | Directly changes the Earth 2023 baseline runtime or generated inputs |
| `active_in_rsa_reference` | Active in the local RSA reference run but not necessarily used by Earth |
| `active_if_matching_carrier_exists` | Applies only if the corresponding carrier/component exists in Earth |
| `inactive_2023` | Present in the scenario row but has no effect for model year 2023 |
| `expansion_only` | Relevant to expansion/planning years, not fixed 2023 validation |
| `rsa_reference_only` | Helps describe the RSA benchmark but does not drive Earth runtime |
| `structural_run_control` | Required to make the scenario run, but not a dispatch/calibration parameter |
| `unused_or_stale` | Present but not used by the current path |
| `unknown_requires_check` | Effect cannot be established from local evidence |

The key deliverable is not just "what is in `S_2023BM`" but "which columns actually matter for the Earth 2023 calibrated baseline."

## Acceptance Criteria

Accept Module 13k if:

- `data/za_audit/za_2023_input_provenance_classification.csv` exists and covers the accepted baseline path.
- `data/za_audit/za_2023_scenario_settings_effective.csv` exists and covers every `S_2023BM` scenario column.

- The audit clearly distinguishes observed Eskom 2023 data from scenario assumptions.
- Local `S_2023BM` construction is documented and not described as upstream RSA GitHub content.
- The audit clearly distinguishes active scenario drivers from inherited/no-op settings.
- Files with no 2023 effect are classified as such.

- The audit identifies any unknown or weakly sourced inputs.
- Module 13l can use the classification to decide what to package and how to label it.

Reject or block if:

- the audit cannot tell which files/fields are actually used at runtime
- the audit claims all inputs are measured 2023 data
- `S_2023BM` is described as upstream RSA without evidence
- unknown provenance is left implicit
